# CQRS/ES Platform in Go (Watermill + Postgres + oapi-codegen)

## Context

This is a brand-new, currently-empty repository (`/home/sage/git/timadorus-platform`). The goal is to
stand up a DDD-flavored CQRS/Event-Sourcing platform in Go that manages six related domain concepts
(User, Universe, Campaign, Character, Entity, Object) for what looks like a tabletop-RPG-style
application: Users create Universes, run Campaigns inside them as Gamemasters, and play Characters
(each auto-paired with an Entity) inside those Campaigns.

Key constraints driving the design:
- Strict DDD layering (domain / application / infrastructure), open for new aggregate types and new
  projections without modifying existing framework code.
- PostgreSQL is the *only* storage backend — both the event store and every projection's read models.
- Watermill is the event-bus library, using **NATS JetStream** as the pub/sub transport (confirmed),
  with Postgres remaining the system of record via a transactional outbox.
- HTTP command and query APIs are both spec-first OpenAPI 3, with server code generated by
  **oapi-codegen** (confirmed).
- Deployment is **three separate Go binaries** (confirmed): `command-api`, `projector`, `query-api`.
- Basic JWT bearer-auth scaffolding is in scope (confirmed); the identity provider itself is not.
- Aggregate IDs are **server-generated** (confirmed).
- The six aggregate types have a real ownership hierarchy (gathered from the user, see §2), not just a
  flat id+name shape — this drives non-trivial invariants (non-empty Gamemaster/Creator lists,
  mandatory Player) and one cross-aggregate creation flow (Character auto-creates an Entity).

## 1. Key Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Module layout | Single Go module, no `go.work` | 3 binaries + shared `internal/` packages must stay in lockstep with the event schema and deploy from the same commit. `internal/` visibility already gives the encapsulation needed. Revisit only if the ES framework is later extracted as a standalone library. |
| HTTP router | `gorilla/mux` | oapi-codegen has a first-class `gorilla-server` generator target; `mux.Router.Use` takes standard `func(http.Handler) http.Handler` middleware, so the same net/http-based JWT/request-validator middleware chain works unchanged. |
| oapi-codegen mode | **strict-server** | Handlers get typed request structs in, typed union response types out — the compiler forces every handler to return a response shape the spec actually defines (real contract enforcement, not just codegen convenience). |
| Postgres driver | `jackc/pgx/v5` (pool) | Native jsonb, context-aware, current idiomatic choice. |
| Event bus | Watermill + `watermill-nats/v2` (JetStream) | Per requirements. |
| Migrations | `golang-migrate/migrate/v4`, one directory per schema owner (event store, outbox, each projection) | A new projection ships its own migrations without touching others (open/closed). |
| JWT/JWKS | `lestrrat-go/jwx/v2` (or `MicahParks/keyfunc`) + `oapi-codegen/nethttp-middleware`'s `OapiRequestValidatorWithOptions` | One middleware gives schema validation (→ 400) *and* auth enforcement declared via the spec's `securitySchemes`. |
| Generics usage | One: `eventsourcing.Repository[T Aggregate]` | Genuinely removes duplicated load/save/optimistic-concurrency code across 6 aggregate types. Nothing else is generic. |
| Aggregate IDs | Server-generated UUIDs | Confirmed by user — simpler client contract; no idempotency-key mechanism needed for v1. |
| Cross-aggregate creation (Character+Entity) | Single ACID Postgres transaction via an ambient-tx `UnitOfWork`, not a saga | All aggregate types share the same Postgres event store, so a saga's eventual-consistency cost buys nothing here — see §4.4. |

## 2. Domain Hierarchy

```
User (independent, top-level account)

Ruleset (independent, top-level — referenced by Campaign, never owned by a Universe)
 └── description: string, mutable via a dedicated command
 └── references: []string, mutable via a dedicated command (whole-list replace)

Universe
 └── Creators: Set<User>, non-empty, mutable (add/remove)

Campaign
 └── belongs to exactly one Universe (immutable parent ref)
 └── references exactly one Ruleset (immutable — set at creation, never changeable; create a
     new Campaign to use a different Ruleset)
 └── Gamemasters: Set<User>, non-empty, mutable (add/remove)

Entity
 └── belongs to exactly one Universe (immutable parent ref)

Object
 └── belongs to exactly one Universe (immutable parent ref)

Character
 └── belongs to exactly one Campaign (immutable parent ref)
 └── references exactly one Entity — auto-created together with the Character
 └── Player: exactly one User, mandatory, mutable via reassignment only (no "unset")
```

Every aggregate type minimally supports `Create` + `Rename`; the relationship-bearing types add the
commands implied by the diagram above (add/remove Creator or Gamemaster, reassign Player). Every
aggregate type additionally carries an `isArchived` flag and an `Archive` command (§4.6) — aggregates
are **never deleted** through the API, only archived; physical removal is an out-of-scope external
housekeeping process (§13).

**Read/write import-graph enforcement:** each aggregate's domain events live in their own `events/`
sub-package (structs + `EventType()` + registry hookup only, no business logic). `command-api` imports
the full `domain/<agg>` package (aggregate + invariants + events). `projector` and `query-api` import
**only** `domain/<agg>/events` and the projection/query packages — never `internal/domain/*` invariant
code or `internal/eventsourcing`. This makes the CQRS read/write separation a compile-time fact, not
just a convention.

## 4. Domain Layer

### 4.1 Generic framework (`internal/eventsourcing`)

```go
type Aggregate interface {
    AggregateID() uuid.UUID
    Version() int
    Apply(event Event)   // mutate state; used both for replay and after Raise
}

type Base struct { id uuid.UUID; version int; pending []Event }
func (b *Base) Raise(event Event) { /* apply to self via owning aggregate, bump version, queue */ }

type Event interface { EventType() string }  // versioned suffix, e.g. "universe.created.v1"

type Registry struct{ /* event-type string -> factory func() Event, for JSON replay */ }

type EventStore interface {
    Append(ctx context.Context, aggregateType string, id uuid.UUID, expectedVersion int, events []Event) error
    Load(ctx context.Context, aggregateType string, id uuid.UUID) (events []Event, version int, err error)
}
var ErrConcurrencyConflict = errors.New("concurrency conflict")
var ErrAggregateNotFound   = errors.New("aggregate not found")

type Repository[T Aggregate] struct { /* store, aggregateType, registry, newBlank func(uuid.UUID) T */ }
func (r *Repository[T]) Load(ctx context.Context, id uuid.UUID) (T, error) { /* Load -> replay via Apply */ }
func (r *Repository[T]) Save(ctx context.Context, agg T) error             { /* Append(pending, agg.Version()) */ }
```

Every aggregate module constructs one `Repository[*<Type>]` and gets Load/Save with optimistic
concurrency for free — this is the one generic that earns its keep across all 6 types.

### 4.2 Reference aggregate: Universe (collection invariant)

```go
type Universe struct {
    eventsourcing.Base
    name     string
    creators map[uuid.UUID]struct{}
    archived bool
}

var (
    ErrCreatorsRequired = errors.New("universe requires at least one creator")
    ErrLastCreator       = errors.New("cannot remove the last creator of a universe")
    ErrArchived          = errors.New("universe is archived")
)

func NewUniverse(name string, creatorIDs []uuid.UUID) (*Universe, error) {
    if len(dedupe(creatorIDs)) == 0 { return nil, ErrCreatorsRequired }
    u := &Universe{}
    u.Raise(&events.UniverseCreated{ID: uuid.New(), Name: name, CreatorUserIDs: dedupe(creatorIDs)})
    return u, nil
}

func (u *Universe) RemoveCreator(userID uuid.UUID) error {
    if u.archived { return ErrArchived }
    if _, ok := u.creators[userID]; !ok { return ErrCreatorNotFound }
    if len(u.creators) == 1 { return ErrLastCreator }   // the invariant
    u.Raise(&events.CreatorRemoved{UniverseID: u.AggregateID(), UserID: userID})
    return nil
}
func (u *Universe) AddCreator(userID uuid.UUID) error { /* checks !u.archived, then idempotent add, then Raise CreatorAdded */ }

// Archive is idempotent (no-op, no event, if already archived) and — like every other
// mutating command on this aggregate — is the one command NOT guarded by `if u.archived`,
// since archiving an already-archived aggregate must succeed rather than error.
func (u *Universe) Archive() error {
    if u.archived { return nil }
    u.Raise(&events.UniverseArchived{UniverseID: u.AggregateID()})
    return nil
}

func (u *Universe) Apply(e eventsourcing.Event) {
    switch ev := e.(type) {
    case *events.UniverseCreated:  u.creators = toSet(ev.CreatorUserIDs); u.name = ev.Name
    case *events.CreatorAdded:     u.creators[ev.UserID] = struct{}{}
    case *events.CreatorRemoved:   delete(u.creators, ev.UserID)
    case *events.UniverseRenamed:  u.name = ev.Name
    case *events.UniverseArchived: u.archived = true
    }
}
```

`Campaign.RemoveGamemaster` is the identical shape (`gamemasters map[uuid.UUID]struct{}`).
`Character.SetPlayer` is the single-mandatory-reference variant — no removal command, only
reassignment, rejecting `uuid.Nil`:

```go
func (c *Character) SetPlayer(userID uuid.UUID) error {
    if c.archived { return ErrArchived }
    if userID == uuid.Nil { return ErrPlayerRequired }
    if userID == c.playerUserID { return nil }  // idempotent no-op
    c.Raise(&events.PlayerChanged{CharacterID: c.AggregateID(), NewPlayerUserID: userID})
    return nil
}
```

Every aggregate type follows the same `archived bool` + `Archive()` + `if a.archived { return ErrArchived }`
guard shape (§4.6) — repeated per type, not templated, per the same copy-adapt philosophy already used
for Create/Rename.

### 4.3 Cross-aggregate reference validation

A command service is scoped to its own aggregate type **plus** a `Repository[U]` for every aggregate
type it must validate against; `Load` is used purely as an existence check (or, for Campaign→Character,
to pull data needed downstream):

```go
type CampaignService struct {
    campaigns eventsourcing.Repository[*campaign.Campaign]
    universes eventsourcing.Repository[*universe.Universe] // existence-check only
    rulesets  eventsourcing.Repository[*ruleset.Ruleset]     // existence-check only
    users     eventsourcing.Repository[*user.User]          // existence-check only
}

func (s *CampaignService) CreateCampaign(ctx context.Context, cmd CreateCampaignCmd) (uuid.UUID, error) {
    universe, err := s.universes.Load(ctx, cmd.UniverseID)
    if err != nil {
        return uuid.Nil, fmt.Errorf("%w: universe %s", ErrParentNotFound, cmd.UniverseID)
    }
    if universe.IsArchived() {
        return uuid.Nil, fmt.Errorf("%w: universe %s", ErrParentArchived, cmd.UniverseID)
    }
    rs, err := s.rulesets.Load(ctx, cmd.RulesetID)
    if err != nil {
        return uuid.Nil, fmt.Errorf("%w: ruleset %s", ErrParentNotFound, cmd.RulesetID)
    }
    if rs.IsArchived() {
        return uuid.Nil, fmt.Errorf("%w: ruleset %s", ErrParentArchived, cmd.RulesetID)
    }
    for _, id := range cmd.GamemasterUserIDs {
        u, err := s.users.Load(ctx, id)
        if err != nil {
            return uuid.Nil, fmt.Errorf("%w: user %s", ErrReferenceNotFound, id)
        }
        if u.IsArchived() {
            return uuid.Nil, fmt.Errorf("%w: user %s", ErrReferenceArchived, id)
        }
    }
    c, err := campaign.NewCampaign(cmd.UniverseID, cmd.Name, cmd.GamemasterUserIDs)
    if err != nil { return uuid.Nil, err }
    return c.ID(), s.campaigns.Save(ctx, c)
}
```

Same pattern for `AddGamemaster`/`RemoveGamemaster`, `AddCreator`/`RemoveCreator`, `SetPlayer`, and
`CreateCharacter` (validates Campaign, derives its `UniverseID` for the auto-created Entity).

**Accepted tradeoff, not a bug:** this is a point-in-time check against the event store, not a
relational FK — different aggregate types don't share a table. This is safe because **no aggregate
type ever has its event stream truncated or removed** — the only "removal" mechanism is `Archive`
(§4.6), which appends a marker event rather than deleting anything, so `Load` always succeeds for any
id that was ever created and existence, once true, can never regress to false through the API. The
validation in `CreateCampaign`/`CreateCharacter`/`AddGamemaster`/etc. additionally checks
`!referenced.IsArchived()` (§4.6) so that *new* relationships can't be formed against an archived
aggregate — existing relationships formed before archiving remain valid and are never retroactively
invalidated.

### 4.4 Cross-aggregate creation: Character + Entity

Creating a Character must also create an Entity. Since every aggregate type shares the *same* Postgres
event store, this is done as a single ACID transaction spanning two aggregate appends — not a saga —
because there is no transactional boundary between the two writes to pay eventual-consistency costs
for.

To do this without threading `pgx.Tx` through the generic `Repository[T]`/`EventStore` interfaces (which
would break their storage-agnosticism), the transaction is made **ambient** via context:

```go
// internal/eventstore/postgres/tx.go
func WithTx(ctx context.Context, tx pgx.Tx) context.Context { /* context.WithValue */ }

func (s *Store) Append(ctx context.Context, aggType string, id uuid.UUID, expectedVersion int, events []eventsourcing.Event) error {
    if tx, ok := txFromContext(ctx); ok {
        return s.appendTx(ctx, tx, aggType, id, expectedVersion, events) // caller owns commit/rollback
    }
    tx, err := s.pool.Begin(ctx)
    if err != nil { return err }
    if err := s.appendTx(ctx, tx, aggType, id, expectedVersion, events); err != nil { tx.Rollback(ctx); return err }
    return tx.Commit(ctx)
}
```

```go
// internal/eventsourcing/unit_of_work.go — opt-in helper, only used by multi-aggregate command services
type UnitOfWork struct{ tx pgx.Tx }
func NewUnitOfWork(ctx context.Context, b TxBeginner) (*UnitOfWork, context.Context, error)
func (u *UnitOfWork) Commit(ctx context.Context) error
func (u *UnitOfWork) Rollback(ctx context.Context) error
```

```go
func (s *CharacterService) CreateCharacter(ctx context.Context, cmd CreateCharacterCmd) (characterID, entityID uuid.UUID, err error) {
    campaignAgg, err := s.campaigns.Load(ctx, cmd.CampaignID) // existence check + need its UniverseID
    if err != nil { return uuid.Nil, uuid.Nil, fmt.Errorf("%w: campaign", ErrReferenceNotFound) }
    if _, err := s.users.Load(ctx, cmd.PlayerUserID); err != nil {
        return uuid.Nil, uuid.Nil, fmt.Errorf("%w: player user", ErrReferenceNotFound)
    }
    ent := entity.NewEntity(campaignAgg.UniverseID(), cmd.Name)
    chr := character.NewCharacter(cmd.CampaignID, ent.ID(), cmd.PlayerUserID, cmd.Name)

    uow, txCtx, err := eventsourcing.NewUnitOfWork(ctx, s.pool)
    if err != nil { return uuid.Nil, uuid.Nil, err }
    if err := s.entities.Save(txCtx, ent); err != nil { uow.Rollback(ctx); return uuid.Nil, uuid.Nil, err }
    if err := s.characters.Save(txCtx, chr); err != nil { uow.Rollback(ctx); return uuid.Nil, uuid.Nil, err }
    if err := uow.Commit(ctx); err != nil { return uuid.Nil, uuid.Nil, err }
    return chr.ID(), ent.ID(), nil
}
```

Single-aggregate handlers (Universe, Campaign, User, Object, standalone Entity create) never touch
`UnitOfWork` — `Append` sees no ambient tx and opens/commits its own, so **zero change to existing call
sites**. Because both `Save` calls run in one transaction, their outbox rows get sequential
`global_seq`/`sequence` numbers in call order, so the relay always publishes `EntityCreated` before
`CharacterCreated`.

> **Implementation note:** during actual implementation, `UnitOfWork` ended up living in
> `internal/eventstore/postgres` rather than `internal/eventsourcing` as originally sketched above —
> see `docs/adr/0004-unit-of-work.md` for why (it avoids a real import cycle, since `UnitOfWork` is
> inherently Postgres-specific).

### 4.5 Event catalog

| Aggregate | Events |
|---|---|
| User | `UserCreated{ID, Name}`, `UserRenamed{Name}`, `UserArchived{}` |
| Universe | `UniverseCreated{ID, Name, CreatorUserIDs}`, `UniverseRenamed{Name}`, `CreatorAdded{UserID}`, `CreatorRemoved{UserID}`, `UniverseArchived{}` |
| Campaign | `CampaignCreated{ID, Name, UniverseID, RulesetID, GamemasterUserIDs}`, `CampaignRenamed{Name}`, `GamemasterAdded{UserID}`, `GamemasterRemoved{UserID}`, `CampaignArchived{}` |
| Entity | `EntityCreated{ID, Name, UniverseID}`, `EntityRenamed{Name}`, `EntityArchived{}` |
| Object | `ObjectCreated{ID, Name, UniverseID}`, `ObjectRenamed{Name}`, `ObjectArchived{}` |
| Character | `CharacterCreated{ID, Name, CampaignID, EntityID, PlayerUserID}`, `CharacterRenamed{Name}`, `PlayerChanged{NewPlayerUserID}`, `CharacterArchived{}` |
| Ruleset | `RulesetCreated{ID, Name, Description, References}`, `RulesetRenamed{Name}`, `RulesetDescriptionChanged{Description}`, `RulesetReferencesChanged{References}`, `RulesetArchived{}` |

Convention: don't duplicate an aggregate's *own* id inside its own payload (the envelope already
carries `aggregate_id`/`aggregate_type`/`version`) — but always include ids that point at a **different**
aggregate type in the payload (`UniverseID`, `CampaignID`, `EntityID`, `PlayerUserID`, etc.), since those
aren't derivable from the envelope and are load-bearing for projections and cross-aggregate validation.
`<Type>Archived` carries no payload beyond the envelope for the same reason.

### 4.6 Archiving (soft-removal, never physical delete)

Every aggregate type — not just Universe — gets an `archived bool` field, an `IsArchived() bool`
getter, an idempotent `Archive()` command (no-op if already archived, otherwise raises `<Type>Archived`
and sets `archived = true` in `Apply`), and a guard at the top of every *other* mutating command
(`Rename`, `AddCreator`/`RemoveCreator`, `AddGamemaster`/`RemoveGamemaster`, `SetPlayer`, and
`CreateCharacter`'s implicit `Entity`/`Character` creation) that rejects with `ErrArchived` (mapped to
HTTP 409) once archived. There is no `Unarchive` command in v1 — archiving is one-way, matching the
"archive, don't delete" framing from the requirement; add `Unarchive` later if a real need surfaces.

This resolves the framing of §4.3's tradeoff cleanly: aggregates are **additive-only** for their entire
lifetime (Create → any number of mutations → optionally Archive), so `Load`-based existence checks stay
valid forever, and cross-aggregate validation additionally checks `!IsArchived()` before letting an
archived aggregate be used in a **new** relationship (new Gamemaster, new Creator, new Player, new
Campaign under a Universe, etc.) — already reflected in the `CreateCampaign` sketch in §4.3.

**Cascading is explicitly out of scope for v1** (open question, §13): archiving a Universe does *not*
automatically archive its Campaigns/Entities/Objects, and archiving a Campaign does not automatically
archive its Characters. Each aggregate's `Archive` command is independent; a consumer that wants
"archive this whole tree" issues one `Archive` call per aggregate.

**Physical deletion / event-log pruning is explicitly not part of this platform's command surface.**
`Archive` is a soft, additive marker event — it never truncates an event stream or removes rows from
`events`/`outbox`. Reclaiming storage for long-archived, unreferenced aggregates (or compacting old
segments of the event log) is an **external housekeeping process** to be designed later, decoupled
from the command/query APIs described here.

## 5. Event Store Schema (Postgres)

```sql
CREATE TABLE events (
    global_seq     BIGSERIAL PRIMARY KEY,
    aggregate_id   UUID NOT NULL,
    aggregate_type TEXT NOT NULL,
    version        INT NOT NULL,
    event_type     TEXT NOT NULL,
    payload        JSONB NOT NULL,
    metadata       JSONB NOT NULL DEFAULT '{}',   -- correlation_id, causation_id, actor subject
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now(),
    UNIQUE (aggregate_id, version)                 -- optimistic concurrency
);
CREATE INDEX idx_events_aggregate ON events (aggregate_id, version);

CREATE TABLE outbox (
    id             BIGSERIAL PRIMARY KEY,
    global_seq     BIGINT NOT NULL REFERENCES events (global_seq),
    aggregate_id   UUID NOT NULL,
    aggregate_type TEXT NOT NULL,
    version        INT NOT NULL,
    event_type     TEXT NOT NULL,
    payload        JSONB NOT NULL,
    metadata       JSONB NOT NULL,
    published_at   TIMESTAMPTZ,
    created_at     TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX idx_outbox_unpublished ON outbox (id) WHERE published_at IS NULL;
```

`Append` writes to `events` and `outbox` in the **same transaction** — the transactional-outbox pattern
that eliminates the Postgres/NATS dual-write problem.

**Snapshotting is explicitly out of scope for v1** — given the minimal id+name(+small collections)
contract, streams stay tiny even after many renames/add/remove operations. Revisit only if measured
stream length in production grows large enough to matter.

**Optimistic concurrency note:** the `expectedVersion` check matters far more for *updates* on an
existing id (Rename, AddCreator/RemoveCreator, SetPlayer) than for *creation*, since server-generated
UUIDs make same-id creation races effectively impossible — don't mistake it for dead code on the create
path.

> **Implementation note:** the `outbox` table gained a `version INT NOT NULL` column beyond the
> original sketch above, and `internal/bus.Envelope` (the wire format published to NATS) carries
> `AggregateID`/`AggregateType`/`Version` in addition to `EventType`/`Payload`/`Metadata` — this is what
> actually makes §4.5's "don't duplicate an aggregate's own id in its payload" convention work, since a
> projector needs *something* to tell it which aggregate an event happened to.

## 6. Outbox Relay

- Runs as a background goroutine embedded in **command-api** (not a 4th binary — it's the only writer
  of the event store, and the topology is fixed at 3 services). Built as its own package
  (`internal/outbox`) so it could be extracted into a standalone deployment later without a redesign.
- **Polling, not LISTEN/NOTIFY**, for v1: `SELECT ... FROM outbox WHERE published_at IS NULL ORDER BY id FOR UPDATE SKIP LOCKED LIMIT N` every ~200ms. Fewer moving parts, no missed-notification edge cases; ~100-300ms added read-model latency is acceptable. LISTEN/NOTIFY is a clean, separable future optimization.
- **Ordering:** a single **active** relay publishes strictly in `id`/`global_seq` order to NATS
  JetStream, subject `events_<aggregate_type>` (one subject per aggregate type — see implementation
  note below on the separator character). Each projection's consumer processes serially (one goroutine,
  in-order ack), so total order is preserved, which trivially preserves per-aggregate order too. This
  trades some throughput for correctness-by-construction; sharding is a later scaling concern, not a v1
  requirement.
- **HA without breaking ordering:** if multiple command-api replicas run, `pg_advisory_lock`
  (`internal/outbox/leader.go`) ensures only one replica's relay goroutine is actively publishing;
  non-leader replicas periodically retry acquiring the lock (failover).
- **Marking published:** `UPDATE outbox SET published_at = now() WHERE id = $1` right after a successful `Publish`, in the same relay loop iteration.

> **Implementation note:** `watermill-nats/v2`'s JetStream auto-provisioning uses the raw topic string
> as the **stream name** too (not just the subject), and NATS stream names may not contain `.`
> (reserved for subject hierarchy). So the actual subject convention is `events_<aggregate_type>`
> (underscore), not the originally-sketched `events.<aggregate_type>` (dot).

## 7. Projection Framework

```go
type Projector interface {
    Name() string                 // durable consumer name AND checkpoint table key, e.g. "universe-read-model"
    Subjects() []string           // e.g. []string{"events_universe"}
    Handle(ctx context.Context, tx pgx.Tx, env Envelope) error
}
type Envelope struct {
    GlobalSeq                          int64
    AggregateID                        uuid.UUID
    AggregateType                      string
    Version                            int
    EventType                          string
    Payload, Metadata                  json.RawMessage
}
```

- One watermill `Router` per projector, each with its own durable JetStream consumer (`Name()` as the
  durable name), `Retry` middleware for transient DB errors, and a poison-queue/dead-letter handler so
  one permanently-broken message doesn't block that projection's entire consumer.
- **Idempotent checkpointing:** `projection_checkpoints (projection_name PK, last_global_seq, updated_at)`. Per message: begin a Postgres tx → skip/no-op+ack if `env.GlobalSeq <= last_global_seq` (handles NATS at-least-once redelivery) → `Handle` (writes read-model tables) → update checkpoint → commit → then Ack. A crash between commit and Ack just causes a safe no-op redelivery.
- **Adding a projection without touching existing ones:** a new package under `internal/projection/<name>/` with its own migrations, `Projector` impl, and read-model tables. The only shared-code change is one line in `cmd/projector/main.go`'s explicit registration list — deliberately explicit (not blank-import/`init()` magic) for discoverability.
- **Router is decoupled from NATS:** `internal/projection.Router` takes a `SubscriberFactory` (`func(durableName string) (message.Subscriber, error)`) rather than constructing a NATS subscriber internally — production wiring (`cmd/projector/main.go`) supplies one backed by `internal/bus.NewSubscriber`; tests supply one backed by Watermill's in-memory `gochannel` pub/sub, which is what makes the idempotent-replay test in §11 possible without a real NATS broker.

### Read-model schema (hierarchy-aware)

```sql
CREATE TABLE users_read_model (
    id UUID PRIMARY KEY, name TEXT NOT NULL, is_archived BOOLEAN NOT NULL DEFAULT false, updated_at TIMESTAMPTZ NOT NULL
);

CREATE TABLE universes_read_model (
    id UUID PRIMARY KEY, name TEXT NOT NULL, is_archived BOOLEAN NOT NULL DEFAULT false, updated_at TIMESTAMPTZ NOT NULL
);
CREATE TABLE universe_creators (
    universe_id UUID NOT NULL REFERENCES universes_read_model(id), -- same-projection FK: safe
    user_id     UUID NOT NULL,                                     -- cross-projection: soft ref, no FK
    PRIMARY KEY (universe_id, user_id)
);

CREATE TABLE campaigns_read_model (
    id UUID PRIMARY KEY, name TEXT NOT NULL, universe_id UUID NOT NULL,
    is_archived BOOLEAN NOT NULL DEFAULT false, updated_at TIMESTAMPTZ NOT NULL
);
CREATE INDEX ON campaigns_read_model (universe_id);
CREATE TABLE campaign_gamemasters (
    campaign_id UUID NOT NULL REFERENCES campaigns_read_model(id), -- same-projection FK: safe
    user_id     UUID NOT NULL,
    PRIMARY KEY (campaign_id, user_id)
);

CREATE TABLE entities_read_model (
    id UUID PRIMARY KEY, name TEXT NOT NULL, universe_id UUID NOT NULL,
    is_archived BOOLEAN NOT NULL DEFAULT false, updated_at TIMESTAMPTZ NOT NULL
);
CREATE INDEX ON entities_read_model (universe_id);

CREATE TABLE objects_read_model (
    id UUID PRIMARY KEY, name TEXT NOT NULL, universe_id UUID NOT NULL,
    is_archived BOOLEAN NOT NULL DEFAULT false, updated_at TIMESTAMPTZ NOT NULL
);
CREATE INDEX ON objects_read_model (universe_id);

CREATE TABLE characters_read_model (
    id UUID PRIMARY KEY, name TEXT NOT NULL,
    campaign_id UUID NOT NULL, entity_id UUID NOT NULL, player_user_id UUID NOT NULL,
    is_archived BOOLEAN NOT NULL DEFAULT false, updated_at TIMESTAMPTZ NOT NULL
);
CREATE INDEX ON characters_read_model (campaign_id);
CREATE INDEX ON characters_read_model (player_user_id);
```

Every list-shaped query-api endpoint (`GET .../campaigns`, `GET .../characters`, etc.) excludes
`is_archived = true` rows by default (implemented as unconditional filtering in v1's `ListByUniverse`/
`ListByCampaign` repository methods — the `?includeArchived=true` opt-in described below was planned
but not implemented in the initial build); single-resource `GET .../{id}` endpoints always return the
resource regardless of archived state, with `isArchived` in the response body so clients can tell.

**Policy:** a real Postgres `REFERENCES` FK is only safe between tables maintained by the *same*
projector (e.g. `campaign_gamemasters → campaigns_read_model`). Any column pointing into a table owned
by a *different* projector (`campaigns_read_model.universe_id`, `characters_read_model.campaign_id`,
etc.) stays a plain indexed UUID — there's no cross-consumer ordering guarantee between independent
projections. Practical consequence: a query-api join from `characters_read_model` to
`entities_read_model` could, for a brief window right after creation, outrun the Entity projector.
Treat this as the same pre-existing class of read-model lag every projection already has, not a new bug
— query-api should tolerate a nullable joined name rather than erroring.

**Migration tracking:** each schema owner (`eventstore`, `projection_checkpoint`, and each
`projection_<aggregate>`) gets not just its own migration directory but its own golang-migrate
`schema_migrations_<name>` tracking table (via `x-migrations-table`) — they're independent version
sequences that happen to share one physical database, not one linear history. See the `Makefile`'s
`migrate-up`/`migrate-down` targets, which loop over the schema-owner list.

## 8. Command API

- Spec-first: `api/command/openapi.yaml` with `components.securitySchemes.bearerAuth` and
  `security: [{bearerAuth: []}]` per mutating operation; `oapi-codegen` (strict-server + gorilla-server +
  embedded-spec) generates types + `StrictServerInterface`.
- **Nested routes matching ownership** (not flat + body parent id) — the parent reference is immutable
  and set at creation, so it belongs in the path; this also gives oapi-codegen a required, typed path
  parameter for the parent, making a missing parent a clean 404 versus a missing body-referenced user
  being a 422.

```
POST   /users
PATCH  /users/{userId}
POST   /users/{userId}/archive                        -- idempotent, 200 whether or not already archived

POST   /universes                                   { name, creatorUserIds }
PATCH  /universes/{universeId}
POST   /universes/{universeId}/archive
POST   /universes/{universeId}/creators/{userId}
DELETE /universes/{universeId}/creators/{userId}     -- 409 if last

POST   /universes/{universeId}/campaigns             { name, rulesetId, gamemasterUserIds }
PATCH  /campaigns/{campaignId}
POST   /campaigns/{campaignId}/archive
POST   /campaigns/{campaignId}/gamemasters/{userId}
DELETE /campaigns/{campaignId}/gamemasters/{userId}  -- 409 if last

POST   /universes/{universeId}/entities              { name }
PATCH  /entities/{entityId}
POST   /entities/{entityId}/archive
POST   /universes/{universeId}/objects                { name }
PATCH  /objects/{objectId}
POST   /objects/{objectId}/archive

POST   /rulesets                                      { name, description?, references? }
PATCH  /rulesets/{rulesetId}
PUT    /rulesets/{rulesetId}/description               { description }
PUT    /rulesets/{rulesetId}/references                { references }
POST   /rulesets/{rulesetId}/archive

POST   /campaigns/{campaignId}/characters             { name, playerUserId }  -- creates Character + Entity atomically, returns both ids
PATCH  /characters/{characterId}
POST   /characters/{characterId}/archive
PUT    /characters/{characterId}/player               { userId }              -- reassign only, no DELETE
```

- Thin handler layer (`internal/httpapi/command/server.go`) implements `StrictServerInterface`,
  translates requests into command-service calls, and maps results/errors via
  `internal/httpapi/command/errors.go` to RFC7807 `application/problem+json`:
  malformed request → 400 (automatic, via the spec-driven request-validator middleware before the
  handler runs) · domain invariant violation (empty name, last-creator removal) → 422/409 ·
  not found (aggregate or a referenced parent/user) → 404 · aggregate or referenced parent/user is
  archived (attempting any mutation other than `Archive` itself, or forming a new relationship
  against an archived aggregate, per §4.6) → 409 · optimistic concurrency conflict → 409 (body
  includes current version for client retry).
- Shared cross-aggregate validation errors live in `internal/command/apperrors`
  (`ErrParentNotFound`, `ErrParentArchived`, `ErrReferenceNotFound`, `ErrReferenceArchived`) so every
  command service that validates against another aggregate type (Campaign→Universe/User,
  Entity/Object→Universe, Character→Campaign/User) reports failures the same way, and
  `internal/httpapi/command/errors.go` has one place to map them to HTTP status codes.

## 10. Auth Middleware (both APIs)

- Both specs declare `bearerAuth`; `oapi-codegen/nethttp-middleware`'s `OapiRequestValidatorWithOptions`
  is mounted via `mux.Router.Use` in each binary, doing schema validation (→ 400) and, for operations
  requiring auth, invoking a configured `AuthenticationFunc` (`internal/auth/jwt.go`) that verifies the
  bearer token (JWKS URL or configured static public key — issuer/IdP out of scope) and stashes claims
  (`sub`, `roles`) into request context via `internal/auth.FromContext`.
- **Pluggability** = JWKS URL / static key / expected issuer & audience are all config-driven
  (`internal/config`) — swapping identity providers needs no code change. This is the full scope of
  auth for v1: no RBAC/authorization-policy engine is built (see Open Questions).
- Phase 5 hardening: reject `alg: none`, enforce an algorithm allow-list, check `exp`/`nbf`/`aud`/`iss`, tolerate only small clock skew.
- **Implementation note:** if neither `JWT_JWKS_URL` nor `JWT_HMAC_SECRET` is configured, both binaries
  fall back to a well-known, loudly-logged insecure dev HMAC secret so `go run ./cmd/command-api` (or
  `query-api`) works out of the box locally — this fallback must never be reachable in a real
  deployment. `internal/auth.NewVerifierFromConfig` is the single shared constructor both binaries call
  for this, to avoid duplicating the JWKS-vs-HMAC-vs-dev-fallback branching logic.

## 11. Testing Strategy

- **Domain unit tests**: given/when/then — build an aggregate from a list of prior events, invoke a
  command method, assert the newly raised event(s)/error. No I/O. Explicitly cover the invariant edge
  cases: removing the last Creator/Gamemaster, setting an empty Player. Implemented for all 6 aggregate
  types (`internal/domain/*/​*_test.go`).
- **Event store / outbox integration tests** (`testcontainers-go` Postgres,
  `internal/eventstore/postgres/store_test.go`): append+load roundtrip, version-reuse →
  `ErrConcurrencyConflict`, outbox row present in the same tx as the event row (and absent if the tx
  rolls back), and — for the `UnitOfWork` path — both Entity and Character rows commit or neither does.
- **Projection tests**: `testcontainers-go` Postgres + Watermill's in-memory `gochannel` pub/sub
  (interface-compatible with NATS, swappable in tests via `internal/projection.Router`'s
  `SubscriberFactory`) — assert read-model state, and specifically assert idempotent replay (deliver
  the same message twice, assert no duplicate junction rows / no state change on the second delivery).
  Implemented for the Universe projector (`internal/projection/universe/projector_test.go`) as the
  representative case.
- **Contract safety:** strict-server generation already gives compile-time contract enforcement. A
  black-box `openapi3filter`-based regression net (validating live HTTP responses against the spec) was
  planned but not implemented in the initial build.
- **End-to-end vertical-slice verification**: rather than a single automated
  `test/e2e/vertical_slice_test.go`, this was exercised manually (`curl`/httpie) against all three
  binaries running against `docker-compose` (Postgres + NATS JetStream) at the end of every phase —
  see §12's phase history and the Verification checklist below for the exact scenarios covered.
  Automating this as a proper Go test is a reasonable follow-up.

Implementation notes:
- **Correlation IDs**: `internal/observability.WithCorrelationID`/`CorrelationID` thread a
  per-HTTP-request id (generated or propagated via `X-Request-Id`) through
  `internal/eventstore/postgres.Store.Append`'s `metadata` column (`eventMetadata{CorrelationID,
  CausationID}` — causation is set equal to correlation for v1, since every event in an Append
  call has exactly one direct cause, the inbound request; a real distinct causation chain isn't
  needed yet), which the outbox relay copies verbatim into `bus.Envelope.Metadata`, which
  `internal/projection.Router` decodes back out (`Envelope.CorrelationID()`) for its log lines.
- **Metrics** (`internal/observability/metrics.go`, exposed at `/metrics` via `promhttp.Handler()`
  on all 3 binaries): `timadorus_http_request_duration_seconds` (command-api/query-api, labelled
  by matched *route template* not raw path, to keep cardinality bounded),
  `timadorus_event_append_duration_seconds`, `timadorus_outbox_publish_lag_seconds`,
  `timadorus_projection_lag_seconds` (needed adding a `CreatedAt` field to `bus.Envelope`, populated
  from `outbox.created_at`, beyond the original §7 sketch), and
  `timadorus_projection_events_total{result="ok|retry|dead_letter"}`.
- **Health/readiness**: `internal/observability.HealthzHandler`/`ReadyzHandler` (the latter pings
  the Postgres pool). Mounted at `/healthz`, `/readyz`, `/metrics` on all 3 binaries — the
  projector gained its own small unauthenticated HTTP server (`PROJECTOR_ADDR`, default `:8083`)
  for this, since it previously had no HTTP surface at all. On command-api/query-api these paths
  are exempted from both OpenAPI schema validation and JWT auth via `internal/auth.Middleware`'s
  `operationalPaths` skip-list (`nethttpmiddleware.Options.Skipper`), since they aren't part of
  either public API contract.
- **Poison-queue/DLQ**: `internal/projection.Router` now tracks consecutive-failure counts
  per message UUID (process-local, resets on restart) and, after `defaultMaxAttempts` (5), records
  the message to a new `projection_dead_letters` table (`internal/projection/checkpoint/deadletter.go`,
  migration `0002_projection_dead_letters` under the `projection_checkpoint` schema owner) and Acks
  it rather than Nacking forever — otherwise one permanently-broken message would block that
  projection's entire single-consumer stream indefinitely.
- **Graceful shutdown**: command-api now waits (`sync.WaitGroup`) for the outbox relay goroutine to
  observe context cancellation and release its `pg_advisory_lock` before the process exits, rather
  than firing-and-forgetting it — avoids a fast restart racing the new instance's leader election.
- **JWT hardening**: `jwt.WithAcceptableSkew` (60s) added; algorithm-confusion/`alg: none` defense
  turns out to already be structural in jwx v3's `jwt.WithKeySet` (it requires every key to carry an
  explicit `alg` and refuses to verify against a key whose `alg` doesn't match the token header — the
  header's claimed algorithm is never trusted on its own), so no separate allow-list check was needed
  beyond documenting why.
- **Dockerfiles**: `Dockerfile.command-api`/`.projector`/`.query-api` at the repo root, multi-stage
  (`golang:1.26-alpine` builder → `gcr.io/distroless/static-debian12:nonroot` runtime, `CGO_ENABLED=0`).
  Built and smoke-tested against the real `docker-compose` Postgres/NATS (`/healthz`, `/readyz`,
  `/metrics` all confirmed working from inside the container).
- **CI**: added `go mod tidy` (no-diff) and `go generate` (no-diff, proves specs/codegen stay in
  sync) checks to the existing build/vet/test job, plus a separate lint job. The lint job is
  `continue-on-error: true`: no golangci-lint release (v1 or v2) yet ships a toolchain that can
  type-check a module declaring `go 1.26` in `go.mod` — it's a hard panic in `go/types` on an older
  analyzing toolchain, not something a golangci-lint config can route around. `go vet` remains the
  enforced static check until golangci-lint catches up.
- **Not automated** (documented gaps, not silently dropped): an automated end-to-end
  `test/e2e/vertical_slice_test.go` (§11 already flagged this; the Phase 1-4 verification scenarios
  were all run manually instead) and an outbox-relay multi-replica HA/failover drill (the
  `pg_advisory_lock` leader-election mechanism was built and is exercised implicitly by every
  single-replica run, but a real concurrent-replica failover test was not performed).

## 13. Open Questions / Assumptions (flagged, not silently decided)

1. **Delete semantics**: resolved — there is no hard-delete command for any aggregate type; `Archive`
   (§4.6) is the only "removal" mechanism, is soft and additive-only, and physical event-log pruning /
   hard deletion of long-archived aggregates is explicitly deferred to a future **external
   housekeeping process**, decoupled from the command/query APIs. This is what keeps §4.3's
   existence-check tradeoff safe indefinitely, not just "for now."
2. **Archive cascading**: does archiving a Universe cascade-archive its Campaigns/Entities/Objects, and
   does archiving a Campaign cascade-archive its Characters? **Not built in v1** — each aggregate's
   `Archive` command is independent and must be called per-aggregate; revisit if a real "archive this
   whole tree in one call" need surfaces.
3. **Event versioning/upcasting**: a `.v1` suffix convention is adopted in event-type strings and the registry is keyed by full type string (future-proofing), but no upcasting framework is built — deliberate scope cut.
4. **Snapshotting** is out of scope for v1 given small streams; revisit if measured stream length grows.
5. **Authorization (RBAC) beyond JWT validation**: claims (`sub`, `roles`) are exposed to handlers, but no per-aggregate authorization policy is implemented (e.g. "only a Gamemaster of this Campaign may add a Character," or "only a Creator may archive a Universe") — real gap to close before production use, needs product/security input. Given the domain now has real ownership (Creators, Gamemasters, Player), this is more load-bearing than in a flat model and worth prioritizing early in a follow-up.
6. **Deployment target**: Docker Compose assumed for local dev; Kubernetes manifests not built in v1.
7. **Query API pagination/filtering**: only "list all under a parent" + "get by id" are planned; list endpoints unconditionally exclude archived rows in v1 (the `?includeArchived=true` opt-in described in earlier drafts of this plan was not implemented); further pagination/filtering criteria undefined.
8. **TLS termination**: the requirement says HTTPS; either terminate at a reverse proxy/ingress (typical) or configure certs in the Go binaries directly — actual deployment topology (not yet specified) determines which.
9. **NATS subject/stream design**: single JetStream stream, one subject per aggregate type
   (`events_<type>`, underscore not dot — see §6's implementation note — not partitioned by aggregate
   id), with strictly serial relay publish + serial per-projection consumption for simple, correct
   ordering. Trades throughput for correctness-by-construction; sharding is an explicit future scaling
   concern.

query-api HTTP calls and prints every response as JSON to stdout — a scriptable operator tool
for the platform, analogous in spirit to `kubectl`. **Status: done**, verified end to end
against the live services (user/universe/campaign/entity/character create, rename, archive,
add/delete gamemaster including the last-gamemaster-invariant 409, the atomic
Character+Entity creation, and interactive id prompting with persistence).

The Ruleset aggregate has been added to the platform as a top-level, parentless aggregate,
following the same `create`/`rename`/`archive`/`get` command pattern as Entity and Object.
Like User and Universe, Ruleset supports a bare `list ruleset` command with no parent-scoping
flag. As the first aggregate with mutable fields beyond `name`, Ruleset introduces dedicated
commands `set description` and `set references` to mutate those fields, extending the `set`
verb (previously used only for Character's `set player`) to cover field-level mutations. The
new bare `list user` and `list universe` commands have been added in parallel, completing the
ability to list all top-level aggregates without a parent-scoping requirement.

### 14.1 Command shape

`timadorusctl <verb> <resource> [args...] [flags]` — verbs map directly to HTTP semantics,
resources are the singular aggregate/relationship name:

| Verb | HTTP | Meaning |
|---|---|---|
| `create` | POST (primary creation) | Create a new aggregate |
| `rename` | PATCH | Rename an aggregate |
| `archive` | POST `.../archive` | Archive an aggregate (idempotent) |
| `add` | POST (sub-resource) | Add a user to a collection relationship (creator/gamemaster) |
| `delete` | DELETE (sub-resource) | Remove a user from a collection relationship |
| `set` | PUT | Mutate a single-value field or reference (player, description, references, etc.) |
| `get` | GET (single) | Fetch one aggregate/projection by id |
| `list` | GET (collection) | List a collection, optionally scoped to a parent (bare for User/Universe/Ruleset) |

Examples (the two given in the original request, plus one more to show the pattern holds):

```
POST /users                                    -> timadorusctl create user <name>
POST /universes                                -> timadorusctl create universe <name> <creatorUserId>...
POST /universes/{universeId}/campaigns         -> timadorusctl create campaign <name> <rulesetId> <gamemasterUserId>...
DELETE /campaigns/{campaignId}/gamemasters/{userId} -> timadorusctl delete gamemaster <userId>
PUT /characters/{characterId}/player           -> timadorusctl set player <characterId> <userId>
```

### 14.2 Id-defaulting: narrow scope, tracked context

`timadorusctl` tracks three things in a local config file (`~/.config/timadorusctl/config.json`,
`timadorusctl config show`/`set-user`/`set-universe`/`set-campaign`): the authenticated user,
the current universe, and the current campaign. The defaulting rule is deliberately **narrow**:

- Tracked defaults fill in **only the parent id of a create/add/delete/list command** — the
  current universe when creating a campaign/entity/object or mutating a universe's Creators;
  the current campaign when creating a character or mutating a campaign's Gamemasters. Each
  such command also accepts an explicit `--universe`/`--campaign` flag to override the
  default for that one call.
- The id of the aggregate a command **acts on** (the rename/archive/get/set target, e.g.
  `<campaignId>` in `rename campaign <campaignId> <name>`) is **always an explicit CLI
  argument**, never defaulted — even though Universe and Campaign have tracked "current"
  values. This avoids a footgun where a bare `rename campaign <name>` would silently target
  whatever campaign happened to be current.
- Cross-aggregate references (creator/gamemaster/player user ids) are **always explicit
  arguments** too. The tracked "current user" (the authenticated identity) is informational
  only — `config show` displays it, but no command auto-fills a userId argument from it. There
  is no tracked "current character" or "current entity/object" (only user/universe/campaign
  are tracked, per the original request), so those ids are always explicit as well.
- When a parent id is needed and neither the flag nor the tracked default is set, the CLI
  interactively prompts for it on stderr (stdout is reserved for JSON API responses — prompts,
  confirmations, and errors all go to stderr) and **persists the answer as the new current
  value** so it isn't asked again.

### 14.3 Convention: every new aggregate type or command gets a matching CLI command

**This is a standing rule for future work on this platform, not just a description of what
exists today.** Whenever a new aggregate type is added (following the Phase 4 "mechanical
replication" pattern — plan §12) or a new command is added to an existing aggregate, add the
corresponding `timadorusctl` command(s) in the same change:

- A new parented, no-collection-invariant aggregate (the Entity/Object shape) gets exactly
  the five commands `object.go`/`entity.go` already show: `create <resource> <name>`
  (with the appropriate parent flag), `rename`, `archive`, `get`, `list` (scoped to that
  parent). Copy-adapt one of those two files — this mirrors the domain layer's own copy-adapt
  convention (plan §4.2).
- A new aggregate with a collection invariant (the Universe/Campaign "Creators"/"Gamemasters"
  shape) additionally gets `add <relationship> <userId>` / `delete <relationship> <userId>` /
  `list <relationship>`, following `universe.go`'s Creators or `campaign.go`'s Gamemasters
  commands as the template.
- A new single-mandatory-reference command (the Character "Player" shape) gets a `set
  <field> <targetId> <userId>` command under the shared `setCmd`, following `character.go`'s
  `set player`.
- If a brand-new HTTP verb/semantic is introduced that doesn't fit `create`/`rename`/
  `archive`/`add`/`delete`/`set`/`get`/`list`, don't silently overload one of these — pick a
  new verb that names what the operation actually does, add it to `App`'s verb-command set in
  `root.go`, and record the choice (and why the existing verbs didn't fit) here in §14.1.
- If the new id-parameter doesn't obviously fit the narrow-scope rule in §14.2 (for example: a
  future aggregate parented by two different aggregate types, or a command needing a *target*
  id that arguably should be defaultable), don't guess — the id-defaulting scope was a
  deliberate, explicit product decision (see git history around this section), so flag the
  ambiguity and ask before extending the rule.

### 14.4 Not built

- No `timadorusctl` Dockerfile — it's an operator/client tool meant to run on a workstation
  against a remote deployment, not a server process, so it doesn't fit the Phase 5 "Dockerfile
  per binary" scope (plan §12, which is specifically about the three *server* binaries).
- No shell-completion install step beyond cobra's built-in `timadorusctl completion <shell>`.
- No automated CLI test suite yet (verified manually against the live stack, same as the
  platform's own end-to-end verification — plan §11's "not automated" note applies here too).
